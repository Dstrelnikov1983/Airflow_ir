FAB-аутентификация: архитектура

Flask AppBuilder (FAB) — фреймворк безопасности, встроенный в Airflow Webserver.

Поддерживаемые методы AUTH_TYPE:
  • AUTH_DB — локальная БД Airflow (по умолчанию)
  • AUTH_LDAP — корпоративный LDAP/AD
  • AUTH_OAUTH — OAuth2 / OpenID Connect
  • AUTH_REMOTE_USER — заголовок от прокси
Ключевые параметры webserver_config.py:
  • AUTH_TYPE — метод аутентификации
  • AUTH_USER_REGISTRATION — авторегистрация
  • AUTH_USER_REGISTRATION_ROLE — роль по умолчанию
  • AUTH_ROLES_MAPPING — маппинг групп в роли
Браузер пользователя
↓ HTTPS
Airflow Webserver (FAB)
↓ AUTH_OAUTH
Keycloak / LDAP (IdP)
↓ Токен
RBAC: роль → ресурсы

OAuth2 и LDAP интеграция

LDAP — для корпоративного AD РЖД:

# webserver_config.py — LDAP
from flask_appbuilder.security.manager import AUTH_LDAP

AUTH_TYPE = AUTH_LDAP
AUTH_LDAP_SERVER = "ldap://ad.rzd.ru"
AUTH_LDAP_USE_TLS = True
AUTH_LDAP_SEARCH = "DC=rzd,DC=ru"
AUTH_LDAP_BIND_USER = (
    "CN=svc-airflow,OU=ServiceAccounts,DC=rzd,DC=ru"
)
AUTH_LDAP_BIND_PASSWORD = "{{ from Lockbox }}"
AUTH_LDAP_UID_FIELD = "sAMAccountName"
AUTH_LDAP_GROUP_FIELD = "memberOf"

# Маппинг групп AD -> роли Airflow
AUTH_ROLES_MAPPING = {
    "CN=grp-airflow-engineers,"
    "OU=Groups,DC=rzd,DC=ru": ["DataEngineer"],
    "CN=grp-airflow-analysts,"
    "OU=Groups,DC=rzd,DC=ru":  ["DataAnalyst"],
    "CN=grp-tceh15-operators,"
    "OU=Groups,DC=rzd,DC=ru":  ["DutyOperator"],
    "CN=grp-airflow-managers,"
    "OU=Groups,DC=rzd,DC=ru":  ["Manager"],
}
AUTH_ROLES_SYNC_AT_LOGIN = True
AUTH_USER_REGISTRATION = True
AUTH_USER_REGISTRATION_ROLE = "Viewer"

OAuth2 — для Keycloak / Яндекс ID:

# webserver_config.py — OAuth2
from flask_appbuilder.security.manager import AUTH_OAUTH

AUTH_TYPE = AUTH_OAUTH
OAUTH_PROVIDERS = [{
    "name": "keycloak",
    "icon": "fa-key",
    "token_key": "access_token",
    "remote_app": {
        "client_id":  "airflow-tceh15",
        "client_secret": "{{ Secret from Lockbox }}",
        "server_metadata_url": (
            "https://auth.rzd.ru/realms/tceh15"
            "/.well-known/openid-configuration"
        ),
        "client_kwargs": {
            "scope": "openid email profile groups"
        },
    },
}]

RBAC: роли и права доступа

Airflow использует ролевую модель Flask AppBuilder. Роли создаются через CLI, API или UI.

Роль DAG Variables Connections Logs Admin
DataEngineer R/W/X R/W R/W R —
DataAnalyst R/X R — R —
DutyOperator R/X — — R —
Manager R — — R —
ITAdmin R/W/X R/W R/W R W

R — чтение, W — запись, X — запуск, — нет доступа

↓ Variable.get() / BaseHook.get_connection()

↓ YC Service Account Key
Yandex Lockbox API
↓ Encrypted secret

Fernet Key: шифрование at-rest

Что шифрует Fernet Key?
  • Пароли Connections в БД Airflow
  • Variables с пометкой is_encrypted=True
  • Extra-поля Connections (JSON)
Принцип работы:
  • Симметричное шифрование (AES-128-CBC + HMAC-SHA256)
  • Ключ генерируется один раз при установке
  • Хранится в airflow.cfg или env-переменной
  • Переменная: AIRFLOW__CORE__FERNET_KEY
  • Потеря ключа = потеря всех зашифрованных данных!
# Генерация нового Fernet Key
from cryptography.fernet import Fernet

key = Fernet.generate_key()
print(key.decode())
# ZmDfcTF7_60GrrY167zsiPd67pEvs0aGOv2oasOM1Pg=
# Добавление в Yandex Lockbox (рекомендуется)
yc lockbox secret create \
  --name airflow-fernet-key \
  --payload '[{
    "key": "fernet_key",
    "text_value": "ZmDfcTF7_60GrrY167zsiPd67pEvs0aGOv2oasOM1Pg="
  }]'

# Передача через переменную окружения при старте
export AIRFLOW__CORE__FERNET_KEY=$(
  yc lockbox payload get \
    --name airflow-fernet-key \
    --key fernet_key
)
Best practice: никогда не коммитить Fernet Key в Git. Использовать Secrets Manager или env-переменные.

# Создание через Airflow API (Python)
from airflow.models import Connection
from airflow import settings

conn = Connection(
    conn_id="glonass_api",
    conn_type="http",
    host="api.glonass-rzd.ru",
    schema="https",
    extra={
        "Authorization": "Bearer {{ lockbox_token }}"
    }
)
session = settings.Session()
session.add(conn)
session.commit()
session.close()

HTTPS через nginx: конфигурация

Пользователь
↓ HTTPS :443 (TLS 1.2/1.3)
nginx (reverse proxy)
SSL termination
↓ HTTP :8080 (localhost)
Airflow Webserver
Сертификаты:
  • Let's Encrypt (certbot) — для public-facing
  • Yandex Certificate Manager — для YC
  • Корпоративный CA — для internal
# /etc/nginx/sites-available/airflow-tceh15
server {
    listen 443 ssl;
    server_name airflow.tceh15.rzd-sib.ru;

    ssl_certificate     /etc/ssl/tceh15/fullchain.pem;
    ssl_certificate_key /etc/ssl/tceh15/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # Security headers
    add_header Strict-Transport-Security
        "max-age=31536000" always;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;

    location / {
        proxy_pass         http://127.0.0.1:8080;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For
                           $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto https;
        proxy_read_timeout 300s;
    }
}

# Редирект HTTP -> HTTPS
server {
    listen 80;
    server_name airflow.tceh15.rzd-sib.ru;
    return 301 https://$server_name$request_uri;
}

Аудит-лог и мониторинг доступа

Что логирует Airflow (FAB Audit Log):
  • Успешный и неудачный вход (login / login_failed)
  • Запуск DAG / Task (dag.trigger)
  • Изменение Variables / Connections
  • Создание / удаление пользователей
  • Изменение ролей (role.add / role.delete)
  • Просмотр Log-файлов задач
Таблицы в БД Airflow:
log — все события аудита
dag_run — запуски DAG
task_instance — выполнение задач 
# Выгрузка аудит-лога для ТЧЭ-15
import pandas as pd
from sqlalchemy import create_engine

engine = create_engine(
    "postgresql://airflow:pass@pg.rzd-sib.ru/airflow"
)

query = """
SELECT
    l.dttm          AS event_time,
    l.dag_id,
    l.event,
    l.owner         AS username,
    l.extra
FROM log l
WHERE l.dttm >= NOW() - INTERVAL '7 days'
  AND l.event IN (
      'login_failed',
      'dag.trigger',
      'variable.edit',
      'connection.edit'
  )
ORDER BY l.dttm DESC
LIMIT 500;
"""

df = pd.read_sql(query, engine)
print(df.to_string())

# Алерт при login_failed > 5 за 10 минут
failures = df[df["event"] == "login_failed"]
if len(failures) > 5:
    print("ALERT: Возможная brute-force атака!")

DAG-level Access Control в Airflow 2.x

Начиная с Airflow 2.0 можно ограничить доступ к конкретному DAG через параметр access_control:

# dags/locomotive_telemetry.py
from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime

dag = DAG(
    dag_id="locomotive_telemetry",
    description="Сбор телеметрии локомотивов ТЧЭ-15",
    schedule_interval="*/15 * * * *",
    start_date=datetime(2024, 1, 1),
    catchup=False,
    access_control={
        "DataEngineer": {
            "can_dag_read",
            "can_dag_edit"
        },
        "DutyOperator": {
            "can_dag_read",
            "can_dag_edit"
        },
        "DataAnalyst": {
            "can_dag_read"
        },
        "Manager": {
            "can_dag_read"
        },
    },
    tags=["telemetry", "tceh15", "security"],
)
Права DAG-level:
ПравоОписание
can_dag_read Просмотр DAG, логов, графиков
can_dag_edit Запуск, пауза, очистка Run
Важно: DAG-level права работают поверх глобальных RBAC-ролей. Пользователь с ролью Viewer не запустит DAG, даже если прописан в access_control.
Best practice ТЧЭ-15: для оперативных DAG (реакция на инцидент) предоставлять can_dag_edit роли DutyOperator.

  • OAuth2 / Keycloak
  • LDAP / Active Directory
  • MFA для Admin UI
  • Session timeout: 8 ч.
Авторизация
  • RBAC: 5 ролей
  • DAG-level access_control
  • Принцип min privileges

  • Yandex Lockbox (основное)

  • Ротация каждые 90 дней
Транспорт
  • HTTPS / TLS 1.2+
  • nginx reverse proxy
  • HSTS заголовки
  • IP allowlist сети
Мониторинг
  • FAB Audit Log
  • Алерты login_failed
  • SIEM интеграция
  • Ежедневные отчёты
