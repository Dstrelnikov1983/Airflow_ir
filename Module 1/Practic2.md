# 2. Теоретическая часть

## 2.1. Основные компоненты Data Pipeline

### Источник данных (Data Source)

Место, откуда извлекаются
данные. В нашем случае это CSV файлы с транзакциями, которые появляются
ежедневно.

### Извлечение (Extract)

Процесс чтения данных из
источника. Необходимо учитывать:

·
Формат данных
(CSV, JSON, XML и т.д.)

·
Кодировку файлов

·
Размер файлов

·
Частоту появления новых данных

·
Механизм
доступа (локальная FS, S3, FTP и т.д.)

### Валидация (Validate)

Проверка качества и
корректности данных:

·
Проверка
схемы (типы данных, обязательные поля)

·
Бизнес-правила
(диапазоны значений, форматы)

·
Выявление дубликатов

·
Проверка референциальной
целостности

·
Статистические проверки
(выбросы, аномалии)

### Преобразование (Transform)

Обработка и подготовка данных:

·
Очистка
данных (удаление пробелов, нормализация)

·
Обогащение
данных (join
с справочниками)

·
Агрегация (группировка,
суммирование)

·
Вычисление производных метрик

·
Приведение к нужному формату

### Загрузка (Load)

Сохранение обработанных
данных в целевое хранилище.

### Отчетность и уведомления

Информирование
заинтересованных сторон о результатах.

## 2.2. Обработка ошибок

Типы ошибок и стратегии
обработки:


| **Тип ошибки**                             | **Пример**                      | **Стратегия**                             |
| ----------------------------------------------------- | --------------------------------------- | ---------------------------------------------------- |
| **Временная**                              | Сетевой                        |                                                    |
| таймаут                                      | Retry с                              |                                                    |
| экспоненциальной задержкой |                                       |                                                    |
| **Системная**                              | Отсутствие файла       | Логирование, алерт, пропуск |
| **Данных**                                    | Невалидная                  |                                                    |
| запись                                        | Сохранение                  |                                                    |
| в dead letter queue                                |                                       |                                                    |
| **Бизнес-логики**                       | Отрицательная сумма | Карантин, ручная проверка    |

# 3. Бизнес-задача

## Контекст:

Вы работаете в компании,
которая занимается онлайн-платежами. Каждую ночь партнерские системы выгружают
файлы с транзакциями за день. Необходимо автоматизировать обработку этих данных
для формирования отчетности.

## Требования:

### Функциональные требования:

·
Ежедневная
обработка CSV файлов с транзакциями (запуск в 02:00)

·
Валидация
данных (проверка дубликатов, корректности сумм)

·
Загрузка валидных данных в
PostgreSQL

·
Создание
агрегированной таблицы с дневной статистикой по каждому партнеру

·
Формирование
и отправка отчета по email

·
Сохранение
невалидных записей в отдельную таблицу для ручной обработки

### Нефункциональные требования:

·
Обработка должна завершаться до
06:00

·
Максимальное
время на обработку одного файла — 30 минут

·
Логирование всех операций

·
Уведомления при ошибках

·
Идемпотентность
(возможность перезапуска без дублирования)

·
Мониторинг прогресса выполнения

## Формат данных:

CSV файл с транзакциями содержит следующие поля:


| **Поле**         | **Тип**         | **Описание**   | **Валидация**   |
| ---------------------- | -------------------- | ------------------------ | -------------------------- |
| **transaction_id**   | string             | Уникальный   |                          |
| ID                   | Не пустой, |                        |                          |
| уникальный |                    |                        |                          |
| **timestamp**        | datetime           | Дата и время | Формат ISO 8601    |
| **partner_id**       | integer            | ID партнера    | > 0                      |
| **amount**           | decimal            | Сумма             | > 0, <= 1000000          |
| **currency**         | string             | Валюта           | RUB, USD,                |
| EUR                  |                    |                        |                          |
| **status**           | string             | Статус           | success, failed, pending |
| **customer_id**      | string             | ID клиента      | Не пустой        |
