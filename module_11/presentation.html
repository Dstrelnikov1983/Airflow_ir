Типы исполнителей (Executors)

Executor определяет, где и как запускаются задачи DAG

Executor Параллельность Инфраструктура Типичное применение
SequentialExecutor 1 задача SQLite Разработка, тестирование DAG
LocalExecutor N процессов Один сервер Пилот на 1 VM в Яндекс Облаке
CeleryExecutor N воркеров Redis/RabbitMQ + PostgreSQL Production (несколько воркеров)
KubernetesExecutor Pod на задачу Kubernetes кластер Перспектива: Managed K8s в YC
Объясните, что выбор executor — ключевое архитектурное решение. Для ТЧЭ-15 с 20-30 одновременными DAG оптимален CeleryExecutor. Попросите слушателей подумать, какой executor они бы выбрали и почему.

LocalExecutor vs CeleryExecutor

LocalExecutor

# airflow.cfg
[core]
executor = LocalExecutor
parallelism = 16
max_active_tasks_per_dag = 8

[database]
sql_alchemy_conn =
  postgresql+psycopg2://
  airflow:pass@localhost/airflow
  • Один хост, несколько процессов
  • Не требует Redis
  • Ограничен ресурсами одной VM
  • Нет горизонтального масштабирования

CeleryExecutor

# airflow.cfg
[core]
executor = CeleryExecutor

[celery]
broker_url =
  redis://redis:6379/0
result_backend =
  db+postgresql://
  airflow:pass@postgres/airflow
worker_concurrency = 8
  • Распределённые воркеры
  • Горизонтальное масштабирование
  • Отказоустойчивость
  • Идеален для 20-30 одновременных DAG

KubernetesExecutor — архитектура

Принцип: каждая задача Airflow запускается как отдельный Kubernetes Pod, который удаляется после завершения 
# airflow.cfg
[core]
executor = KubernetesExecutor

[kubernetes]
namespace = airflow-rzd
worker_container_repository =
  cr.yandex/rzd/airflow-worker
worker_container_tag = 2.8.0
delete_worker_pods = True
delete_worker_pods_on_failure = False
in_cluster = True

Преимущества:

  • Изоляция каждой задачи
  • Авто-масштабирование (HPA)
  • Разные Docker-образы для задач

Недостатки:

  • Cold start ~30 сек (критично для алертов)
  • Сложнее в обслуживании
  • Требует Managed K8s в Яндекс Облаке
На практике: рассматривать как следующий шаг после стабилизации Celery-стека

Grafana — дашборд эксплуатации ТЧЭ-15

Панели дашборда (8 штук):

  • Stat: Running Tasks / Queued Tasks
  • Gauge: Free Worker Slots (0–24)
  • Time Series: DAG Duration p50 / p95
  • Stat: Failed DAG Runs за 24 ч
  • Time Series: Scheduler Heartbeat
  • Table: Перегрев букс (>80°C)
  • Bar: Опоздания поездов (мин)
  • Stat: OTD% (on-time delivery)

Алертинг: Email и Telegram

# dags/utils/alerts.py
import requests
from airflow.hooks.base import BaseHook

TELEGRAM_CONN_ID = "telegram_tche15"


def send_telegram_alert(context):
    """Алерт дежурному инженеру ТЧЭ-15."""
    conn = BaseHook.get_connection(
        TELEGRAM_CONN_ID
    )
    token = conn.password
    chat_id = conn.host

    dag_id = context["dag"].dag_id
    task_id = context["task"].task_id
    exec_date = context[
        "execution_date"
    ].strftime("%d.%m.%Y %H:%M")
    exception = str(
        context.get("exception", "—")
    )[:200]

    msg = (
        f"🚨 AIRFLOW ALERT\n"
        f"DAG: {dag_id}\n"
        f"Task: {task_id}\n"
        f"Время: {exec_date}\n"
        f"Ошибка: {exception}\n"
        f"Дирекция: ТЧЭ-15 НГ"
    )
    requests.post(
        f"https://api.telegram.org"
        f"/bot{token}/sendMessage",
        json={
            "chat_id": chat_id,
            "text": msg,
            "parse_mode": "HTML",
        },
        timeout=10,
    )

# Подключение алертов в DAG

Обслуживание метабазы Airflow

Регулярное обслуживание PostgreSQL БД метаданных

# Очистка устаревших данных
airflow db clean \
  --clean-before-timestamp \
  "2024-01-01 00:00:00" \
  --tables dag_run,task_instance,\
           log,xcom,job \
  --yes

# Проверка состояния метабазы
airflow db check

# Применение миграций при обновлении
airflow db migrate

# Резервное копирование переменных
airflow variables export \
  /backup/vars_$(date +%Y%m%d).json

# Резервное копирование connections
airflow connections export \
  /backup/conns_$(date +%Y%m%d).json
# DAG: автоматическое обслуживание БД
from airflow import DAG
from airflow.operators.bash import (
    BashOperator,
)
from datetime import datetime

with DAG(
    dag_id="db_maintenance_tche15",
    schedule="0 2 * * 0",  # вс, 02:00
    start_date=datetime(2024, 1, 1),
    catchup=False,
    tags=["ops", "tche15", "maintenance"],
) as dag:
    clean = BashOperator(
        task_id="clean_old_dag_runs",
        bash_command=(
            "airflow db clean "
            "--clean-before-timestamp "
            '"{{ macros.ds_add(ds,-90) }}" '
            "--tables dag_run,"
            "task_instance,log,xcom "
            "--yes"
        ),
    )
    vacuum = BashOperator(
        task_id="vacuum_analyze",
        bash_command=(
            'psql "$AIRFLOW__DATABASE__'
            'SQL_ALCHEMY_CONN" '
            '-c "VACUUM ANALYZE;"'
        ),
    )
    clean >> vacuum

Три production-алерта для ТЧЭ-15 → Telegram

Алерт 1: Перегрев букс

Температура буксы > 80°C → критический алерт. Содержит: серию и номер локомотива, ось, температуру, координаты ГЛОНАСС.

Опоздание > 30 мин → уведомление. Содержит: номер поезда, станцию, план vs факт.

Алерт 3: Отказ пайплайна

Падение DAG → немедленный алерт. Содержит: имя DAG, задачу, первые 200 символов ошибки.
