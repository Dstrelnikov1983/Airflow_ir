Зачем создавать кастомные компоненты?

Стандартные провайдеры Airflow
  • PostgresOperator, S3Hook
  • HttpOperator, SparkSubmitOperator
  • SlackWebhookOperator …
✔ Готовые решения для популярных систем
Ограничения провайдеров
  • Нет поддержки внутренних/отраслевых систем
  • Нет интеграции с проприетарными API
  • Нет специфической логики обработки доменных данных
Кастомные компоненты решают:
  • Чтение данных из проприетарных источников по REST/SDK
  • Интеграцию с внутренними бизнес-системами
  • Ожидание готовности данных от внешнего источника
  • Инкапсуляцию доменной бизнес-логики и расчётов
Принцип: создавай кастомный компонент, когда стандартные средства требуют более 30 строк «обёртки» в каждом DAG.

Кастомные Sensors — BaseSensorOperator

Sensor = оператор-ожидатель
  • Наследует BaseSensorOperator
  • Реализует метод poke(context) → bool
  • Вызывается периодически до получения True
  • При False — ждёт и повторяет (poke_interval)
  • При таймауте — поднимает исключение
Режимы работы сенсора:
  • mode='poke' — занимает worker-слот
  • mode='reschedule' — освобождает слот между проверками
Типовой сценарий: внешний источник публикует данные с задержкой — сенсор ждёт появления записей перед запуском обработки.

  • Импортирует классы операторов, хуков, сенсоров

Код: GLONASSHook и LocomotiveTelemetryOperator

Читает телеметрию локомотива из ГЛОНАСС-сервера ТЧЭ-15 и сохраняет в PostgreSQL

from airflow.models import BaseOperator
from airflow.hooks.base import BaseHook
from airflow.sensors.base import BaseSensorOperator
import requests

class GLONASSHook(BaseHook):
    """Hook для подключения к ГЛОНАСС-серверу РЖД."""
    conn_name_attr = "glonass_conn_id"
    default_conn_name = "glonass_default"

    def get_conn(self):
        conn = self.get_connection(self.glonass_conn_id)
        return requests.Session()

    def get_telemetry(self, loco_id: str, date: str):
        session = self.get_conn()
        response = session.get(
            f"{self.conn.host}/api/telemetry",
            params={"loco_id": loco_id, "date": date},
            headers={"Authorization": f"Bearer {self.conn.password}"}
        )
        return response.json()

class LocomotiveTelemetryOperator(BaseOperator):
    """Загружает телеметрию локомотива из ГЛОНАСС в PostgreSQL."""
    template_fields = ["loco_id", "target_date"]

    def __init__(self, loco_id, target_date="{{ ds }}", **kwargs):
        super().__init__(**kwargs)
        self.loco_id = loco_id
        self.target_date = target_date

    def execute(self, context):
        hook = GLONASSHook(glonass_conn_id="rzd_glonass")
        data = hook.get_telemetry(self.loco_id, self.target_date)
        self.log.info(f"Got {len(data)} records for {self.loco_id}")
        return data

Вопрос для обсуждения

Когда лучше создать кастомный оператор, чем использовать PythonOperator с функцией? Дайте пример для интеграции с системой ГЛОНАСС РЖД.
Аргументы ЗА кастомный оператор:
  • Логика используется в 3+ DAG-файлах депо
  • Нужен наглядный отображаемый тип в UI
  • Есть template_fields для Jinja-шаблонов
  • Оператор распространяется по парку дирекции тяги
  • Требуется специфическое управление ошибками ГЛОНАСС
Когда PythonOperator достаточен:
  • Логика уникальна для одного DAG
  • Нет необходимости в повторном использовании
  • Простая задача (<20 строк кода)
  • Прототип или быстрый эксперимент
Практическое правило ТЧЭ-15: если один и тот же callable вставляется в PythonOperator более двух раз — оформляй как отдельный оператор с говорящим именем.

Обсуждение: 5 минут в парах, затем краткие ответы группы (2–3 мин)

Кейс для анализа

Ситуация: ГЛОНАСС-сервер РЖД обновился до API v2, изменились эндпоинты. 15 DAG в ТЧЭ-15 используют GLONASSHook v1 с путём /api/v1/telemetry. Новый эндпоинт: /api/v2/loco/telemetry, структура ответа изменилась. Как безболезненно мигрировать без остановки пайплайнов?
Подходы к миграции:
  • Параметр api_version='v1' с backward-совместимым default
  • DeprecationWarning для старых параметров
  • Версионирование самого хука (v1/v2)
  • Feature flag через Airflow Variables
Главное преимущество Hook:
  • Меняем только один файл — glonass_hook.py
  • Все 15 DAG автоматически получают исправление
  • Если бы логика была в PythonOperator — пришлось бы менять 15 DAG

Стратегия перехода:
  1. Добавляем параметр api_version со старым default
  2. Старые DAG продолжают работать без изменений
  3. Новые DAG сразу пишутся с api_version='v2'
  4. Постепенно переводим существующие DAG
  5. Убираем api_version='v1' в следующем мажоре

Полный GLONASSHook для ТЧЭ-15

Реализация с retry-логикой, кэшированием сессии и поддержкой всех типов ТПС

"""plugins/hooks/glonass_hook.py
Хук для подключения к ГЛОНАСС-серверу ТЧЭ-15 (проприетарный REST API).
Conn Type: HTTP | Conn Id: rzd_glonass
Host: glonass.tche15.rzd | Port: 8443 | Password: 
"""
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry
from typing import Any, Dict, List, Optional

from airflow.hooks.base import BaseHook
from airflow.exceptions import AirflowException


class GLONASSHook(BaseHook):
    """Hook для работы с ГЛОНАСС-сервером ТЧЭ-15."""

    conn_name_attr    = 'glonass_conn_id'
    default_conn_name = 'rzd_glonass'
    conn_type         = 'http'
    hook_name         = 'ГЛОНАСС ТЧЭ-15'

    def __init__(self, glonass_conn_id: str = default_conn_name) -> None:
        super().__init__()
        self.glonass_conn_id = glonass_conn_id
        self._session: Optional[requests.Session] = None
        self._base_url: Optional[str] = None

    def get_conn(self) -> requests.Session:
        """Создаёт HTTP-сессию с Bearer-аутентификацией."""
        if self._session is not None:
            return self._session
        conn = self.get_connection(self.glonass_conn_id)
        self._base_url = f"https://{conn.host}:{conn.port or 8443}"
        session = requests.Session()
        session.headers.update({
            'Authorization': f"Bearer {conn.password}",
            'Content-Type':  'application/json',
        })
        retry = Retry(total=3, backoff_factor=2,
                      status_forcelist=[500, 502, 503, 504])
        session.mount('https://', HTTPAdapter(max_retries=retry))
        self._session = session
        self.log.info("GLONASSHook: подключение к %s", self._base_url)
        return self._session

    def get_telemetry(self, loco_id: str, date: str) -> List[Dict[str, Any]]:
        """Возвращает телеметрию локомотива за дату.
        Поля: timestamp, lat, lon, speed_kmh, buxa_temp_c,
              traction_current_a, voltage_kv, fuel_lph, engine_hours
        """
        session = self.get_conn()
        url = f"{self._base_url}/api/v1/telemetry"
        resp = session.get(url, params={"loco_id": loco_id, "date": date},
                           timeout=30)
        try:
            resp.raise_for_status()
        except requests.exceptions.HTTPError as exc:
            raise AirflowException(
                f"GLONASSHook HTTP {resp.status_code}: {resp.text[:200]}"
            ) from exc
        return resp.json().get('records', [])

    def close(self) -> None:
        if self._session:
            self._session.close()
            self._session = None

Ожидает передачи телеметрии от локомотива на ГЛОНАСС-сервер ТЧЭ-15 после прихода в депо

"""plugins/sensors/loco_data_ready_sensor.py
Сенсор ожидания появления телеметрии локомотива
в ГЛОНАСС-сервере ТЧЭ-15 за указанную дату.
Локомотив передаёт данные при входе в зону Wi-Fi депо.
"""
from airflow.sensors.base import BaseSensorOperator
from airflow.utils.decorators import apply_defaults
from hooks.glonass_hook import GLONASSHook


class LocoDataReadySensor(BaseSensorOperator):
    """
    Ожидает, когда на ГЛОНАСС-сервере появятся данные локомотива.

    :param loco_id:           номер локомотива (напр. 'ВЛ80С-1234')
    :param min_records:       минимальное кол-во записей телеметрии
    :param glonass_conn_id:   ID соединения с ГЛОНАСС-сервером
    """

    template_fields = ('loco_id',)
    ui_color = '#70AD47'

    @apply_defaults
    def __init__(
        self,
        loco_id: str,
        min_records: int = 10,
        glonass_conn_id: str = GLONASSHook.default_conn_name,
        *args,
        **kwargs,
    ) -> None:
        super().__init__(*args, **kwargs)
        self.loco_id         = loco_id
        self.min_records     = min_records
        self.glonass_conn_id = glonass_conn_id

    def poke(self, context: dict) -> bool:
        """Возвращает True, когда данных достаточно для обработки."""
        date = context['ds']
        self.log.info(
            "[LocoDataReadySensor] Проверка: loco=%s date=%s",
            self.loco_id, date,
        )
        try:
            hook    = GLONASSHook(glonass_conn_id=self.glonass_conn_id)
            records = hook.get_telemetry(self.loco_id, date)
            count   = len(records)
            self.log.info("  найдено записей: %d (мин: %d)", count, self.min_records)
            if count >= self.min_records:
                self.log.info("  данные готовы!")
                return True
            self.log.info("  недостаточно записей, ждём...")
            return False
        except Exception as exc:
            self.log.warning("  ошибка проверки: %s", exc)
            return False
